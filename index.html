Reproducing an ML experiment often requires recovering details that its paper and released code leave implicit, and even a successful attempt can leave those decisions buried in conversations or shell histories. ReproBridge preserves them as a refined reproducible artifact: refined code, environment setup, experiment launchers, and a reproduction guide. Across four coding agents on 1,029 tasks, refined artifacts raise mean reproduction success from 76.4% to 92.6% and reduce downstream API spending by 19.7% on average.

  1. 01 · The task

    HELIX, a time-series imputation paper, reports mean absolute error. ReproBridge-Bench turns each selected main-table result into a task anchored by five human-verified reference observations. A new result counts only if it lands inside the task's compatibility interval, [0.12524, 0.13448] for T004 and [0.38442, 0.43878] for T006, and passes an independent execution audit.

  2. 02 · A capable guess

    Opus 5, the strongest raw-code reproducer in the evaluation, starts from the paper and the released code. It restores the paper's architecture but keeps the shipped batch size of 32 and a learning rate of about 6.29×10−4.

  3. 03 · Outside the interval

    Both runs finish, but neither MAE is compatible: 0.15265 for T004 and 0.50527 for T006, each above its interval. Success now hinges on a detail the release leaves implicit.

  4. 04 · Recover and record

    During construction, guide entry A6 identifies repository revision 9760b347, whose architecture matches the paper configuration, as the source for batch size 8 and learning rate 5.75×10−4. The guide records the repository history and architectural match as the rationale; the --paper_config launcher makes the choice executable.

  5. 05 · A fresh session reuses it

    A later session receives the refined artifact, never the construction conversation. Its MAEs, 0.12986 for T004 and 0.41160 for T006, both fall inside their intervals. On HELIX, Opus 5 succeeds on 4 of 9 tasks with raw code and 9 of 9 with the refined artifact.

Overview

Preserve what a reproduction recovers, then measure whether it helps

The work has three parts. A standardized refined reproducible artifact preserves executable procedures and the reasons behind them. An agent workflow constructs these artifacts from a paper and its official repository. ReproBridge-Bench measures whether fresh coding-agent sessions reproduce experiments more reliably with them.

The paper’s condensed guide for SCIQL keeps all twelve section headings in their original order. It links a renamed-package issue to a compatibility launcher and a minimum-episode check, preserving both an executable route and the reason for it.

# Reproducing Table 1 of SCIQL

## What this is

- Table 1: style alignment for CBC, SCBC, and SCIQL.

- Released Circle2D and HalfCheetah datasets; code commit `5389c6e`.

## Hardware

- One GPU per repetition; this guide used NVIDIA H100 80 GB.

## Software

- Python 3.10; JAX 0.5.2; NumPy 2.2.3; PyTorch 2.5.1+cpu.

- JAX runs on the GPU; PyTorch is used for logging.

## Environment setup

```bash

bash setup/01_environment.sh

source .venv/bin/activate

DATA_ROOT=/data bash setup/02_data.sh

```

## Artifacts

- `datasets.zip`: SHA-256 checked; 1,000 episodes per Circle2D dataset.

- No released checkpoints; each experiment trains from scratch.

## Experiments

- G15: SCIQL × circle2d-inplace-v0; one seed, all six style criteria.

```bash

DATA_ROOT=/data OUTPUT_ROOT=/outputs bash experiments/run_G15.sh 0

```

## Repetitions and variance

- Run index = seed; the paper reports a mean over five seeds.

- Use distinct seeds and retain every run, including low-scoring runs.

## Outputs and metrics

- `$OUTPUT_ROOT/G15/run0/metrics.json`, key: `alignment_x100`.

- Unweighted mean over labels, then criteria, multiplied by 100.

## Paths

- `DATA_ROOT`: datasets. `OUTPUT_ROOT`: new measurements and logs.

- `src/datasets/traj2d` links into `$DATA_ROOT/episodes/traj2d`.

## Ambiguities and unspecified details

- A1: use unweighted aggregation; checked against Appendix Table 3.

- A3: released episodes refer to the old package name `style_bench`.

- Adopt aliases to `sciql.core.data` in `src/tools/sciql_launch.py`;

retain the released episode classes.

## Known pitfalls

- Symptom: exit 0 and a plausible CSV, despite loading no episodes.

- Cause: import errors are caught and skipped by the loader.

- Fix: use the compatibility launcher and keep `--min-episodes 1000`.

- Keep smoke outputs separate from full runs (`run<i>.smoke/`).

## What is not covered

- HumEnv: the released datasets and integration code are missing.

- Experiments outside Table 1.

02 · BenchmarkWhat counts as a reproduction

ReproBridge-Bench provides 1,029 tasks from 387 experiments across 36 papers. Each task is anchored by five human-verified reference observations. A result succeeds only if it is numerically compatible with them and survives an independent execution-integrity audit.

From 742 papers to 1,029 tasks

The collection targets main experimental results with accessible official implementations. A task is one own-method measurement in a main table, identified by dataset, metric, reporting statistic, and location; baselines, stand-alone ablations, figures, and appendix-only results are excluded. An experiment can emit several task scores.

Five reproductions, one interval

Five human reproducers on separate servers start from the same pinned raw commit, with separate execution directories and coding-agent sessions. Assuming faithful, independent executions, their mean estimates the expected result and their spread characterizes run-to-run variation. A compatibility interval built from them, fixed across raw and refined-artifact conditions, then decides numerical compatibility for every downstream attempt.

  1. Independent

    Separate servers, directories, and coding-agent sessions from one pinned commit; no reuse of another participant's scripts or measurements, or of refined artifacts or downstream traces.

  2. Human-checked

    Coding-agent assistance is permitted, but humans inspect the scripts, configurations, edits, and measurement extraction actually used.

  3. Pre-committed

    Unspecified repetition and seed choices are fixed before inspecting scores; procedures are not tuned, nor valid measurements repeated, until they approach the published value.

  4. One statistic

    Each observation measures the specified task statistic: a multi-seed mean or best-of-N statistic is one observation, not interchangeable with single-seed scores.

Compatibility interval
I(q)=[ x − r, x + r ]
r=max{t(1+q)/2, 4 s √1 + 15, 0.01 |x|}
x, s
Mean and sample standard deviation of the five reference observations.
q
0.95 by default (t ≈ 2.78); 0.80 for the stricter check (t ≈ 1.53).
√(1 + ⅕)
Accommodates both uncertainty in the reference mean and variation in the new observation; without the floor, this is a Student-t prediction interval.
0.01 |x|
The explicit 1% tolerance floor, active on 197 retained tasks.
Two-sided
A score beyond either bound fails, including one that improves on the published value. The 586 lower-is-better and 443 higher-is-better measurements use the same rule.
Reference variability
V = 100 · (maxi xi − mini xi) / |p|

A task enters the evaluation set only if the published score p lies in I(.95). Stable tasks (Cat. 1) have V ≤ 10; higher-variability tasks (Cat. 2) exceed it.

Five reference observations are a protocol choice, not a guarantee of adequate uncertainty estimation. Numerical compatibility does not certify scientific validity or complete fidelity to the stated experiment.

Measurement model
Y = μ + D + ε
μ
The expected value of the specified statistic when the experiment is faithfully executed. The published score is one observation, not an error-free value of μ.
D
The shift in expectation from execution choices departing from the specified experiment.
ε
Zero-mean variation conditional on those choices.

Repeated measurements can reduce uncertainty about the mean of a fixed procedure, but cannot correct a consistently misexecuted procedure. ReproBridge aims to reduce |D| by preserving procedures and decisions for faithful execution, while ε remains.

An audit behind every match

Matching numbers alone can conceal substituted measurements. An independent Auditor traces each reported value to its output location, execution record, and generating script, and provides no feedback to the Reproducer.

Evidence chain
  1. reported value
  2. output location
  3. execution record
  4. generating script

Ledger timestamps check execution and extraction order; available script and output hashes verify that the inspected files match the recorded versions.

  1. 1Submitted resultNew measurements and execution evidence
  2. 2Mechanical screeningIdentifies leads; unresolved leads need recorded dispositions
  3. 3FinderInspects executed code and records; proposes localized violations
  4. 4RefuterTries to overturn each proposed invalidation
  5. 5PanelOnly if the evidence remains contested
  6. 6VerdictUnsubstantiated findings remain uncertain

Five eligible violation classes

  1. 1Copying a value without measuring it
  2. 2Substituting the measurement instrument
  3. 3Altering an operand used by the intended formula
  4. 4Choosing the reported outcome conditional on observed values
  5. 5Computing the wrong statistic

The Auditor cross-checks executed code, logs, and extracted values to locate copied measurements, altered outputs, or substituted computations.

Invalidation requires all three
  • An eligible violation supported by localized evidence
  • A material effect on the measurement
  • A failed refutation
Not enough on its own
  • A numerical mismatch
  • A crashed run
  • A hardware difference
  • Suspicion without a localized artifact

None of these automatically meets the conditions. Paper–code discrepancies are assessed against the same criteria.

Reproduction success depends jointly on artifact quality and reproducer ability. ReproBridge is primarily intended as a reproducibility check before a paper is submitted and its artifacts are released, and the same format lets third-party reproducers preserve their work to lower the cost of later attempts.

What these results do not show

The limitations stated in the paper's discussion, each linked to the part of this page it qualifies.

01

Conditional evaluation

The evaluation conditions on retained papers, fixed reference regions, and the tested agents; it is not a conference-wide reproduction rate. Five reference observations are a protocol choice, not a guarantee of adequate uncertainty estimation.

The 36 papers were retained from a random sample of 50 of the 241 ICML 2026 Spotlights with code and non-purely-theoretical content.

Related section: 02 · Benchmark ↑
02

Compatibility is not validity

Numerical compatibility does not certify scientific validity or complete fidelity to the stated experiment, and refined artifacts can preserve incorrect assumptions.

Success requires numerical compatibility and no confirmed audit violation.

Related section: 02 · Benchmark ↑
03

Imperfect audits

Automated audits miss some violations, as quantified against human verification.

Of the 39 invalid outcomes identified in human review of 818 outcomes, Codex misses eight and Claude misses 15.

Related section: 02 · Benchmark ↑
04

Workflow and handoff together

Ordinary outputs and refined artifacts come from separate runs with comparable upstream resource use, so the comparison evaluates the construction workflow and resulting handoff together; it does not isolate the effect of reorganizing identical outputs. Component ablations measure losses conditional on the remaining materials.

Related section: 03 · Results ↑
05

Descriptive annotations

Case annotations and variability strata describe patterns rather than isolate causal effects.

Explanations for recovered outcomes come from an agent-assisted case review of 101 model–paper pairs; their counts are not independent causal measurements.

Related section: 05 · Cases ↑
06

Partial cost accounting

API savings concern downstream Reproducer sessions. Construction, independent verification, GPU execution, maintenance, and human review have separate costs; reuse estimates assume fixed prices and savings. Human time savings and comprehension require a separate study.
