02 · BenchmarkWhat counts as a reproduction

ReproBridge-Bench provides 1,029 tasks from 387 experiments across 36 papers. Each task is anchored by five human-verified reference observations. A result succeeds only if it is numerically compatible with them and survives an independent execution-integrity audit.

From 742 papers to 1,029 tasks

The collection targets main experimental results with accessible official implementations. A task is one own-method measurement in a main table, identified by dataset, metric, reporting statistic, and location; baselines, stand-alone ablations, figures, and appendix-only results are excluded. An experiment can emit several task scores.

Five reproductions, one interval

Five human reproducers on separate servers start from the same pinned raw commit, with separate execution directories and coding-agent sessions. Assuming faithful, independent executions, their mean estimates the expected result and their spread characterizes run-to-run variation. A compatibility interval built from them, fixed across raw and refined-artifact conditions, then decides numerical compatibility for every downstream attempt.

  1. Independent

    Separate servers, directories, and coding-agent sessions from one pinned commit; no reuse of another participant's scripts or measurements, or of refined artifacts or downstream traces.

  2. Human-checked

    Coding-agent assistance is permitted, but humans inspect the scripts, configurations, edits, and measurement extraction actually used.

  3. Pre-committed

    Unspecified repetition and seed choices are fixed before inspecting scores; procedures are not tuned, nor valid measurements repeated, until they approach the published value.

  4. One statistic

    Each observation measures the specified task statistic: a multi-seed mean or best-of-N statistic is one observation, not interchangeable with single-seed scores.

Compatibility interval
I(q)=[ x − r, x + r ]
r=max{t(1+q)/2, 4 s √1 + 15, 0.01 |x|}
x, s
Mean and sample standard deviation of the five reference observations.
q
0.95 by default (t ≈ 2.78); 0.80 for the stricter check (t ≈ 1.53).
√(1 + ⅕)
Accommodates both uncertainty in the reference mean and variation in the new observation; without the floor, this is a Student-t prediction interval.
0.01 |x|
The explicit 1% tolerance floor, active on 197 retained tasks.
Two-sided
A score beyond either bound fails, including one that improves on the published value. The 586 lower-is-better and 443 higher-is-better measurements use the same rule.
Reference variability
V = 100 · (maxi xi − mini xi) / |p|

A task enters the evaluation set only if the published score p lies in I(.95). Stable tasks (Cat. 1) have V ≤ 10; higher-variability tasks (Cat. 2) exceed it.

Five reference observations are a protocol choice, not a guarantee of adequate uncertainty estimation. Numerical compatibility does not certify scientific validity or complete fidelity to the stated experiment.

Measurement model
Y = μ + D + ε
μ
The expected value of the specified statistic when the experiment is faithfully executed. The published score is one observation, not an error-free value of μ.
D
The shift in expectation from execution choices departing from the specified experiment.
ε
Zero-mean variation conditional on those choices.

Repeated measurements can reduce uncertainty about the mean of a fixed procedure, but cannot correct a consistently misexecuted procedure. ReproBridge aims to reduce |D| by preserving procedures and decisions for faithful execution, while ε remains.

An audit behind every match

Matching numbers alone can conceal substituted measurements. An independent Auditor traces each reported value to its output location, execution record, and generating script, and provides no feedback to the Reproducer.

Evidence chain
  1. reported value
  2. output location
  3. execution record
  4. generating script

Ledger timestamps check execution and extraction order; available script and output hashes verify that the inspected files match the recorded versions.

  1. 1Submitted resultNew measurements and execution evidence
  2. 2Mechanical screeningIdentifies leads; unresolved leads need recorded dispositions
  3. 3FinderInspects executed code and records; proposes localized violations
  4. 4RefuterTries to overturn each proposed invalidation
  5. 5PanelOnly if the evidence remains contested
  6. 6VerdictUnsubstantiated findings remain uncertain

Five eligible violation classes

  1. 1Copying a value without measuring it
  2. 2Substituting the measurement instrument
  3. 3Altering an operand used by the intended formula
  4. 4Choosing the reported outcome conditional on observed values
  5. 5Computing the wrong statistic

The Auditor cross-checks executed code, logs, and extracted values to locate copied measurements, altered outputs, or substituted computations.

Invalidation requires all three
  • An eligible violation supported by localized evidence
  • A material effect on the measurement
  • A failed refutation
Not enough on its own
  • A numerical mismatch
  • A crashed run
  • A hardware difference
  • Suspicion without a localized artifact

None of these automatically meets the conditions. Paper–code discrepancies are assessed against the same criteria.

Task success
Result lies in the fixed compatibility interval and Not invalidated by the primary Auditor (Codex) = Success

Missing or incompatible results fail. Uncertain audit findings do not count as invalidations.
